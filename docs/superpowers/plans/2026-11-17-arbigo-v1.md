# ArbiGo V1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Livrer la PWA de préparation des rencontres décrite dans le cahier des charges.

**Architecture:** Next.js App Router, Auth.js Credentials/JWT, Prisma 7/MariaDB. Un agrégat de préparation versionné contient les snapshots ; les événements, opérations de synchronisation, appareils, comptes, médias et tâches Push sont stockés séparément. IndexedDB écrit les opérations et l'état local atomiquement avant envoi.

**Tech Stack:** Next.js 16, React 19, TypeScript strict, Prisma 7, MariaDB, Vitest, Playwright, Docker Compose.

**Spec:** `docs/ArbiGo_Cahier_des_charges_V1.md`

## Global Constraints

- Français, thème clair, palette #003287 / #E60028 / #BE965A / #FFFFFF.
- Aucune validation automatique ; clôture manuelle et journal append-only.
- 3 pratiques distinctes ; aucun contenu non vérifié présenté comme officiel.
- Un appareil propriétaire, fencingVersion et quarantaine des opérations révoquées.
- Inventaire réutilisable, sac neuf non coché, instantanés conservés.
- Pas d'export PDF, pas de FMI distante, pas d'IA.

## Review Focus

- Fuseaux Paris et changements d'heure : heures inexistantes/ambiguës rejetées explicitement.
- Double clic et reprise réseau : idempotence, ordre des opérations, aucune perte silencieuse.
- Transfert d'appareil : l'ancien appareil ne peut modifier l'agrégat serveur.
- Historique clos : seuls de nouveaux commentaires séparés restent ajoutables.
- Cache partagé : isolation par compte, purge à la déconnexion.
